What macOS Unlocks

The extra screen real estate and OS capabilities that transform FLO from a mobile app to a desktop power tool.

Persistent Three-Zone Layout

iOS Landscape: Sidebar collapses when detail opens to preserve space.

macOS: ALL THREE zones visible simultaneously. Browse transactions in the middle while viewing details on the right AND navigating categories via the sidebar.

This is the game-changing difference. On mobile, you're trading screen real estate. On macOS, you have enough for true multi-pane workflows.

Shared Layout Code Strategy

One SwiftUI layout engine, multiple platform-specific implementations.

// Pseudocode structure (actual SwiftUI) struct ContentView: View { @Environment(\.horizontalSizeClass) var hSizeClass @Environment(\.verticalSizeClass) var vSizeClass @State var selection: String? @State var showDetail = false var layoutMode: LayoutMode { switch (hSizeClass, vSizeClass) { case (.compact, .regular): return .iphonePortrait case (.compact, .compact): return .iphoneLandscape case (.regular, .regular): #if os(macOS) return .macOS #else return .ipad #endif default: return .ipad } } var body: some View { Group { switch layoutMode { case .iphonePortrait: TabBarNavigation { content } case .iphoneLandscape: HStack { IconSidebar() content } case .ipad, .macOS: HStack { Sidebar() ContentList() if showDetail { DetailPanel() } } } } } }
Same View hierarchy, different layout branching. All three zones use the same models and logic. Layout is purely presentation.

Implementation Strategy

How to build FLO as a truly unified cross-platform app.

Step 1: Define Design System
  • Create FLODesignSystem Swift package
  • Define all colors, fonts, spacing
  • Build reusable components
  • Version control the tokens
Step 2: Build Views with Tokens
  • All UI uses FLODesignSystem
  • No hardcoded colors or sizes
  • SwiftUI for iOS and macOS
  • Shared view hierarchy
Step 3: Platform-Specific Layout
  • Use @Environment size classes
  • #if os(macOS) for platform code
  • Same views, different arrangement
  • Layout logic, not styling logic
Step 4: Platform-Specific Interactions
  • macOS gets keyboard shortcuts
  • macOS gets right-click menus
  • iOS gets swipe gestures
  • Share core data models

The Key Principle: Layout vs. Style

Layout changes based on screen size and platform (iPhone portrait vs. landscape vs. macOS). Style is constant. Colors are always the same. Typography scales are always the same. Components look the same. Only the arrangement of zones and the presence/absence of certain UI elements changes. This is why the same design system works everywhere.
